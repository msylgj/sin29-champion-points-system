# Sprint 1 导入脑暴与取舍

## 候选方向

1. 扩展业务功能：缺少用户提出的新需求，不采用。
2. 主动重构积分计算：风险高且缺少失败证据，不采用。
3. 全量体检后修复最高优先级缺口：可验证、范围明确，采用。
4. 若全部门禁通过，仅沉淀项目真相源和验证证据：符合“不制造工作”约束，采用。

## 缺陷优先级裁决

- P0：数据破坏、认证绕过、核心流程不可用。
- P1：真实门禁失败、稳定复现的核心规则错误、验证入口无法在声明环境运行。
- P2：不影响当前正确性的可维护性或体验问题，登记但不在本 Sprint 顺手修复。

## 选定路径

按 Compose 静态校验、后端测试、前端 lint/test/build、综合脚本的顺序建立基线。任何修复都必须能由失败 gate 或聚焦复现直接证明，并在修复后重跑对应 gate；没有该证据就不改应用代码。
